# OpenSlate gateway contract

Caddy is the default HTTPS gateway for development and Windows/macOS
installations. It is the only component that may bind to a LAN address.
FastAPI and Next.js bind to `127.0.0.1`; PostgreSQL and the file scanner are
never exposed through this gateway.

The contract is deliberately proxy-agnostic:

- `/api/events` goes to FastAPI as an unbuffered, uncompressed SSE stream with
  a 24-hour stream limit.
- `/api` and `/api/*` go to FastAPI.
- every other path goes to Next.js.
- `Host`, `Origin`, `X-Request-ID`, and Caddy's standard forwarding headers
  reach each upstream.
- no CORS headers are generated by the gateway.

For local development, the root Compose `gateway` profile generates the
container-aware configuration and starts the hardened image:

```sh
./scripts/dev.py caddy
```

The generated configuration uses `host.docker.internal` for the host-run
FastAPI and Next.js upstreams. Its local certificate authority persists in the
`caddy-data` volume. `scripts/dev.py` delegates to the environment helper that
generates the container configuration before invoking Compose.

Compose maps the configurable host `GATEWAY_PORT` to Caddy's fixed internal
public listener at `3448`. This keeps the public port independent from the
container contract. The generated configuration also creates an unexposed HTTP
listener at `127.0.0.1:3449` for the container health check. It proxies only
`/api/health` to FastAPI and cannot alter the public gateway's TLS or virtual
host behavior, including an administrator's custom public certificate.

Generate a Caddyfile after selecting the local service ports:

```sh
python3 infra/caddy/generate_config.py \
  --public-host <PUBLIC_HOST> \
  --output <GENERATED_CADDYFILE> \
  --upstream-host 127.0.0.1 \
  --tls-mode internal
```

`internal` uses Caddy's local CA. The installer is responsible for arranging
trust on client devices. For an administrator-provided certificate, pass paths
only; never put PEM values in the generated file or command arguments:

```sh
python3 infra/caddy/generate_config.py \
  --public-host <PUBLIC_HOST> \
  --output <GENERATED_CADDYFILE> \
  --tls-mode custom \
  --cert-file <CERTIFICATE_FILE> \
  --key-file <PRIVATE_KEY_FILE>
```

`--listen-address` defaults to `0.0.0.0`. Use `127.0.0.1` for a host-only
development gateway. The generator accepts only literal IP bind addresses,
valid hostnames/IP public and upstream hosts, valid ports, and absolute certificate paths
without control characters or Caddy interpolation braces.
The upstream defaults to `127.0.0.1`; the Compose environment helper selects
`host.docker.internal` for its container.

Equivalent IIS and nginx examples are in [reference](reference/). Their
operator must configure TLS and their hosting-specific forwarding trust.

The IIS example requires IIS URL Rewrite and Application Request Routing (ARR)
to be installed, ARR proxying enabled, and the site HTTPS binding configured.
Its `allowedServerVariables` list names every `HTTP_*` value read or written by
the rules; configure that list at server level when IIS locks it for delegated
sites. Configure ARR to disable response buffering for `/api/events` and allow
at least a 24-hour upstream response timeout. The example provides routing and
header behavior; those server-level ARR settings are installation prerequisites.
