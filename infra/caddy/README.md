# OpenSlate production gateway contract

Caddy is the HTTPS gateway for production-level testing and Windows/macOS
installations. It is not part of ordinary local development. It is the only
component that may bind to a LAN address.
FastAPI binds to `127.0.0.1`; PostgreSQL and Storage are never exposed
through this gateway.

The repository retains Caddy as an installed, configured, disabled `gateway`
Compose profile. Daily `./scripts/dev.py db`, `./scripts/dev.py containers`,
and `npm run dev` do not start it. After an operator manually prepares the
production-like FastAPI static asset configuration, these commands control the
preview gateway:

```sh
./scripts/dev.py caddy
./scripts/dev.py stop caddy
```

For an isolated production-level Caddy check, run
`uv run python -m tests.fullstack_runner --acceptance-only` from `backend/`.

The contract is deliberately proxy-agnostic:

- `/api/events` goes to FastAPI as an unbuffered, uncompressed SSE stream with
  a 24-hour stream limit.
- `/api` and `/api/*` go to FastAPI.
- every production UI and static asset path goes to FastAPI.
- `Host`, `Origin`, `X-Request-ID`, and Caddy's standard forwarding headers
  reach the FastAPI upstream.
- no CORS headers are generated by the gateway.

Production is the generator default. It has one FastAPI upstream and contains
no frontend port or Node.js runtime:

```sh
python3 infra/caddy/generate_config.py \
  --public-host <PUBLIC_HOST> \
  --output <GENERATED_CADDYFILE> \
  --backend-port <BACKEND_PORT> \
  --tls-mode internal
```

The generator has a single production mode. It routes API, SSE, UI, and static
assets to the FastAPI server, which serves the static frontend export. It has no
Next.js development upstream or frontend port.

`internal` uses Caddy's local CA. The installer is responsible for arranging
trust on client devices. For an administrator-provided certificate, pass paths
only; never put PEM values in the generated file or command arguments:

```sh
python3 infra/caddy/generate_config.py \
  --public-host <PUBLIC_HOST> \
  --output <GENERATED_CADDYFILE> \
  --tls-mode custom \
  --cert-file <CERTIFICATE_FILE> \
  --key-file <PRIVATE_KEY_FILE>
```

`--listen-address` defaults to `0.0.0.0`. The generator accepts only literal IP
bind addresses, valid hostnames/IP public and upstream hosts, valid ports, and
absolute certificate paths without control characters or Caddy interpolation braces.
The upstream defaults to `127.0.0.1`.

Equivalent IIS and nginx examples are in [reference](reference/). Their
operator must configure TLS and their hosting-specific forwarding trust.

The IIS example requires IIS URL Rewrite and Application Request Routing (ARR)
to be installed, ARR proxying enabled, and the site HTTPS binding configured.
Its `allowedServerVariables` list names every `HTTP_*` value read or written by
the rules; configure that list at server level when IIS locks it for delegated
sites. Configure ARR to disable response buffering for `/api/events` and allow
at least a 24-hour upstream response timeout. The example provides routing and
header behavior; those server-level ARR settings are installation prerequisites.
