# Auth behavior map

Baseline: commit fd412418; owners updated for the F7 consolidation on the same base. Paths are under `frontend/tests`. Owners name the file and title only, because line numbers go stale on the next edit; loop titles are quoted as source templates, with `${…}` left unexpanded.

Layer column: `http` runs a browser (every Auth `http` test takes `page`); `isolated` runs in Node without a browser.

D4 marks (consolidation.md D4), in the Source column: `D4: authentication | authorization | data isolation | account isolation | credential concealment` is a denial, concealment or isolation test; `D4: regression-shaped` is a test whose title or comment describes a stale, late, held or hung response (no commit evidence was checked, so these stay protected). `fail-closed` marks a malformed or unavailable read that must not be trusted.

Counts after F7: 6 `http/auth-*` files with 77 expanded runs (baseline 92), and 54 new isolated rows in `isolated/auth/` (workspace start 13, action links 23, MFA status 10, email confirmation 8); `isolated/security/` keeps 34 `test(` sites and 36 runs (baseline 40 and 50) after its link-taking cases moved into the action-link table. Every behavior below names one owner.

Known gaps (no change in F7; each needs a production change and the user's approval): the login failure message mapping (`Retry-After` rounding and the 403/429/503/network copy) is inline in `app/login/page.tsx`, so its ten rows stay in http; the email change failure copy (`signed_out_required`, `email_change_incomplete`, 400/401, other) is inline in `app/auth/email-change/page.tsx`, and the http loop asserts only that an alert appears. Finding: the http other-owner fallback row uses a member with a hidden Access preference, so it lands on OpenView even without the owner check; the isolated row "a preference owned by another account falls back to OpenView" (administrator, Platform preference) is the one that fails when the check is removed.
