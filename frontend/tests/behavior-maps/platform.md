# Platform behavior map

Baseline: commit fd412418 (the Platform specs are unchanged at ad605cdc); owners updated for the F5 consolidation. Paths are under `frontend/tests`. Owners name the file and title only, because line numbers go stale on the next edit; loop titles are quoted as source templates, with `${…}` left unexpanded.

Layer column: `http` runs a browser (every Platform `http` test takes `page`); `isolated` runs in Node without a browser; `isolated (contract)` is a case that `describeContracts` generates from `isolated/contracts/`.

D4 marks (consolidation.md D4), in the Source column: `D4: denial | authorization | data isolation | guest access` is a 401/403/404 refusal or concealment, role or grant gating, or account-switch isolation; `D4: regression-shaped` is a test whose title or comment describes a stale, late, older, held or revoked response (no commit evidence was checked, so these stay protected). `fail-closed` marks a malformed or unavailable read that must not be trusted. `M#`, `P#` and `G#` point at the matrix candidates and duplicate groups of the F5 analysis.

Counts after F5: 6 `http/platform-*` files with 106 expanded runs (baseline 123), 184 new isolated rows in `isolated/platform/` (library files 23, notifications 24, import and export 35, search 18, shared file rules 43, Platform queries 41) and 11 new contract cases in `isolated/contracts/platform-library-notifications-contract.spec.ts`. Every isolated row failed when the production line it owns was broken. Every behavior below names one owner.

Known gaps (each needs a production change and the user's approval): `failureMessage` in `hooks/use-record-import.ts` is not exported, so its admission branches (`mfa_required`, `ip_not_allowed`, 401 with the session recheck, 404) have no owner; Search has the same recheck branch, also unowned (P5). The `NotificationItem` label, destination and time label switch (P1), the CSV reading rules inside `useRecordImport` (P2), the `account.tsx` helpers (P3: device labels beyond three user agents, password and session error mapping) and `platformSectionFromSearch` (P4) are inline or module-private, so their rows stay in http. Upload outcome handling in `files.tsx` (P6) is not proposed for extraction.
