# Access behavior map

Baseline: commit 7ca93d32; owners updated for the F4 consolidation on base 26038f1c. Paths are under `frontend/tests`. Owners name the file and title only, because line numbers go stale on the next edit; loop titles are quoted as source templates, with `${…}` left unexpanded. Short references in the Source column (`ov:16`, `pe:925`, …) name the baseline line of a test at 7ca93d32: `ab` account-boundary, `cp` catalog-paging, `dp` draft-paging, `gr` groups, `me` memberships, `ng` navigation-gating, `ov` overview, `pv` paging-visual (deleted), `pg` paging, `pe` people, `ps` person-security, `ev` security-events, `se` security (all `http/access-<name>.spec.ts`). Source `—` means no criterion, contract, or bug is evident in the test or its comments.

Layer column: `http` runs a browser (every Access `http` test takes `page`); `isolated` runs in Node without a browser; `isolated (contract)` marks a case that `describeContracts("Access", …)` generates from `isolated/contracts/access-contract.spec.ts`.

D4 marks (consolidation.md D4), in the Source column: `D4: denial | authorization | data isolation | guest access` is a 401/403/404 refusal or concealment, role, guest or manager gating, or account-switch isolation; `D4: regression-shaped` is a test whose title or comment describes a stale, late, older or held response (no commit evidence was checked, so these stay protected). `fail-closed` marks a malformed or unavailable read that must not be trusted. The detail identity guard (baseline ev:620) retains its isolated adapter row and its original HTTP concealment/error/Retry journey. `latch:` names the hook that keeps its own refusal latch (`refusalKey`, 401/403 until a fresh Retry); `privileged-read concealment` is the security and events session recheck.

Counts after F4: 156 `test(` sites in 12 `http/access-*` files (183 expanded runs; baseline 161 and 211), 132 isolated tests in `isolated/access/` (baseline 52), and 42 contract cases (baseline 31). Every behavior below names one owner.

Known gaps (no change in F4; each needs a production change and the user's approval): the emitted event sentences and Event type labels are in `helpers/security-event-sentences.ts` with an isolated owner (plan item 25); the person security outcome copy is in `helpers/person-security-outcome.ts` with an isolated owner (plan item 25); `overviewHealth`, `filterGroups`, `sameList`, `changedPatch`, `applyPatch` and the three `*ListOptions` without callers were deleted with their tests (plan item 25); the three refusal latches are separate copies (`use-people-search.ts`, `use-access-catalog.ts`, `use-people-memberships.ts`). Contract findings: `UserRecoveryResponse` declares `local_revocation` and `revoked_sessions` independently while the adapter requires them paired, and `verifyMfa` accepts only `access_token: null` (the cookie-client answer) while the route returns a token to bearer clients; both contract cases pin the paired or cookie answer.
