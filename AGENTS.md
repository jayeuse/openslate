# Repository Guide

## Boundaries

- The root is an orchestration and documentation layer, not a JavaScript or
  Python package. Run npm commands from `frontend/` and uv/Alembic commands
  from `backend/`.
- Local infrastructure is managed by the Supabase CLI. Do not reintroduce
  root container orchestration, a separate database service/UI, a reverse
  proxy, or a local storage mount as the supported development path.
- Backend code is capability-oriented: cross-cutting infrastructure belongs
  in `app/core/`, shared application code in `app/common/`, and domain
  behavior in the matching `app/systems/<capability>/` package.
- `auth`, `users`, `departments`, `modules`, `fields`, and `records` own
  persistence models, schemas, validation, and CRUD routers. Keep domain
  mutations in audited ORM sessions and do not add bulk/raw mutation paths.
- `audit` is an application-only ORM audit system. Supabase Auth, Studio,
  Alembic, direct SQL, Data API operations, and external database clients are
  outside its capture boundary. `AuditLog` is immutable and is never audited
  recursively.
- Supabase Auth owns identities and invitation delivery. The backend's
  Supabase secret key is server-only; browser code uses the publishable key.
  Realtime is restricted by application protocol to private Broadcast
  invalidation events, and Supabase Storage is the only file-storage
  foundation.

## Commands

- Start local platform: `supabase start` from the root.
- Inspect local values: `supabase status -o env`; never commit or report the
  returned keys.
- Backend setup: `cd backend && uv sync && uv run alembic upgrade head`, then
  `uv run python scripts/provision_database_role.py`.
- Admin bootstrap: `cd backend && uv run python scripts/bootstrap_admin.py --email <email> --username <username>`.
- Host backend: `cd backend && uv run uvicorn app.main:app --reload --host 127.0.0.1 --port 8000`.
- Host frontend: export the root `.env` values, then `cd frontend && npm ci && npm run dev -- --hostname 127.0.0.1`.
- Backend verification: `uv run ruff check . && uv run mypy app && uv run pytest`.
- Frontend verification: `npm run lint && npm run typecheck && npm run build && npm run test:e2e`.
- Alembic drift check: `cd backend && uv run alembic check` while local
  Supabase PostgreSQL is running.
- Focused backend test: `uv run pytest tests/test_health.py` or append
  `-k <name>`.
- Focused browser test: `npm run test:e2e -- tests/home.spec.ts --project=chromium`.
- Destructive local reset: `supabase db reset`, followed by
  `cd backend && uv run alembic upgrade head`.

## Runtime Details

- The Supabase CLI provides local PostgreSQL 17, Auth, Realtime, Storage,
  Studio, and Mailpit. Supabase migrations and seeds are disabled because
  Alembic exclusively owns the application schema.
- Supabase's Data API does not expose the application schema. FastAPI owns
  application data reads and writes; do not add direct Data API writes.
- Local Next.js development proxies `/api/*` to `BACKEND_URL` (normally
  `http://localhost:8000`). The frontend and backend run directly on the host.
- `MIGRATION_DATABASE_URL` uses the local database owner for Alembic;
  `DATABASE_URL` uses the provisioned `openslate_runtime` login. `SUPABASE_URL`,
  the publishable key, secret key, Auth redirect URL, JWT issuer, JWKS URL, and
  audience are required for the Auth integration.
- Usernames are normalized to lowercase, passwords require at least 12
  characters, global signup is disabled while email login remains available to
  invited users, and administrator invitations are sent through Supabase Auth.
- PostgreSQL-specific models use `JSONB`; do not substitute SQLite for
  migration or schema verification.
- Domain SQLAlchemy models inherit `app/core/base_model.py`, which supplies
  UUIDv7 `id`, lifecycle timestamps, soft-delete state, and nullable
  `performed_by`. `AuditLog` is the immutable exact-schema exception.
- Roles are seeded by the application Alembic migration with `admin` and
  `member`; current authorization remains role-name based.
- Audit snapshots are minimal before/after JSONB diffs; sensitive fields are
  redacted, and normal audited ORM entity mutations are required for writes.
- Loopback URLs and published ports must be verified with `supabase status`.
  Do not use database network restrictions that break Supabase
  service-to-service connections.

## Framework guidance

  guide under `frontend/node_modules/next/dist/docs/` before changing
  framework conventions or configuration.
