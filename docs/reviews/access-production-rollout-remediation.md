## Subsequent review findings and corrections

- A concurrent last-administrator race was reproduced in isolated PostgreSQL, then closed by serializing administrator changes on the shared Administrator role before user locks. The retained interleaving regression passes.
- Directory Activity/Recent activity filters and unreachable status choices were removed because the authoritative directory API cannot answer them. Role, Group, Department, and Expiry remain available as advanced filters. Expired people and services no longer display or count as Active.
- A follow-up frontend review caught a sample-operation clock mismatch in last-administrator checks. The affected commands now use the supplied operation time; a red/green expiry-boundary regression and independent re-review pass.
- The requested `deep_review` became available in the later review session. It confirmed the concurrency and clock repairs, then found that setup-only administrators could use the new user-session routes. Three route-level regressions first reproduced successful responses, then passed with HTTP 401 after the shared admin gate required a completed identity. Narrow `deep_review` re-review marked this correction **Pass**.
- The continued deep review found no-op rule PATCH/batch responses could pair stale data with a newer policy revision after commit/rollback. Both paths now return the revision captured while locked; focused regressions failed before the correction and passed afterward, and narrow deep re-review marked the fix **Pass**.
- The continued review also found that closing an assigned, non-default department could make all Access views fail to load. Snapshot hydration now includes closed department names while new-assignment choices remain active-only. The identity editor shows selected closed memberships with a removal control, including after a refreshed server snapshot changes; focused mapper/helper regressions and narrow deep re-review passed.
