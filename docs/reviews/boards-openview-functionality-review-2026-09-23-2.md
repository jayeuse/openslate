## C. Findings

### P1 — high

**BR3-12 — A standalone test-mode manifest can bypass the required live database-ownership gate (new Phase 0 security defect).** `backend/app/core/config/instance.py:126-224` accepts process-supplied flags and a self-written mode-`0600` manifest listing a loopback URL, then returns `None` rather than a live target. An existing unit test at `backend/tests/operations/test_instance_guard.py:232-248` explicitly accepts such a manifest. Consequently Alembic at `backend/migrations/env.py:37-59` and role provisioning at `backend/operations/provision_database_role.py:343` skip live host/port/database/user/cluster/container/volume checks for a standalone test-mode process. If that process is supplied valid credentials for another loopback `openslate` database, it can attempt migrations or role changes there; no wrong-target write was observed. Preserve the disposable runner, but bind its manifest to verifiable run-owned container/network/port/volume/cluster identity, check Docker ownership at every mutating host-process entry, and verify connected database/user/cluster before DDL/DML. The bootstrap role path and containerized scanner need their respective preflight. Regression: reject a matching self-written manifest without a live owned instance and each wrong volume/port/cluster/database/user; then verify the normal disposable runner still provisions and migrates. This is P1 because the approved isolation contract protects other databases from potentially destructive operations, though exploitability requires credentials.

### P2 — medium

**BR3-01 — Ordinary sort and grouping cannot be set in live Views (incomplete CTRL-O05).** A fresh definition begins with `sort: []` at `frontend/src/components/systems/openview/components/server-backed-views-workspace.tsx:151-170`; the routed editor has no setter for ordinary sort or Table/Grid grouping. Its group picker is only for Kanban lanes. The earlier Views editor exposed those controls, and the backend accepts stable sort/group requests. A user cannot create the ordered/grouped saved View promised by Phase 2. Add bounded sort and general group controls within the existing advanced editor; retain six layouts and the query contract. Regression: create a multi-sort, grouped Table View from real records, save/reload, and assert order and membership. Source-confirmed missing binding; P2 because release urgency beyond this scoped workflow is not established.

**BR3-02 — Persisted presentation settings cannot be edited or consistently applied (incomplete CTRL-O07).** `server-backed-views-workspace.tsx:173-191` initializes visible columns, pins, density, wrapping, card size, and card title/detail fields, but the routed controls expose no user editor for these properties. Moreover `visibleFields` at `:606-619` follows catalog order rather than saved column order, and the Table renderer at `:2387` does not consume pins/density/wrapping; card size is also unused. Fields after the first eight are unavailable as visible columns in a new View. Expose these settings in the existing advanced section **and apply them in the relevant renderers**, preserving the present layout. Regression: choose a later field, reorder/pin it, adjust density/card size, save/reload, and assert the visible order and presentation.

**BR3-03 — Record inspection loses filtered-order navigation and safe-link copy (incomplete CTRL-O12/O13).** Opening a live row changes the request to a record-ID search at `server-backed-views-workspace.tsx:496-505`; the linked-record panel at `:1210-1254` offers Return but no adjacent-record or Copy safe link action. The `Previous`/`Next` at `:2443-2470` page the results table, not the inspected record. Users cannot step through matching records or copy the inspected record's identifier-only URL. Preserve the filtered result context for inspector navigation and restore Copy safe link without changing the saved query. Regression: inspect across a page boundary in both directions, copy and reopen the URL, and verify access control.

**BR3-04 — “Unsaved view” silently reselects a personal default (new CTRL-O10 interaction defect).** The selector removes `view` from the URL at `server-backed-views-workspace.tsx:1305-1329`, but `selectedViewId = routedView ?? defaultViewId ?? ""` at `:419-457` immediately selects the saved default. The next Save can update that View instead of creating a separate draft. Keep an explicit local unsaved selection distinct from an implicit default on a clean URL; retain the default behavior on normal entry. Regression: set a default, choose Unsaved view, create/save another View, and verify the default and original remain unchanged. This was reproduced in the preceding synthetic browser review and remains source-confirmed here.

**BR3-05 — Owned saved Views cannot be duplicated (incomplete CTRL-O09).** `saveTarget` points to the owned View (`server-backed-views-workspace.tsx:687`), and the dialog always updates it at `:2621-2629`; no create-copy action is available on the live route. Restore Duplicate in View actions, creating a new ID while preserving the original and revision-checked Save. Regression: duplicate, reload, and assert independent originals/copies.

**BR3-06 — Dirty saved Views lack Reset changes (incomplete CTRL-O11).** The component already holds `baseDraft` and computes `dirty` (`server-backed-views-workspace.tsx:448-459`), but View controls at `:1532-1627` offer no direct discard/reset. Restore a local reset to the selected saved revision without a server mutation; keep navigation guards for other exits. Regression: change filters and presentation, Reset, then assert original state and no write request.

**BR3-07 — Membership filters cannot be typed normally and operator changes retain the wrong value shape (new CTRL-O04 defect).** At `server-backed-views-workspace.tsx:2067-2086`, typing `A,` for “is one of” immediately parses to `["A"]` and the controlled input renders `A`, erasing the comma before a second value can be typed; pasting an entire list is only a workaround. Switching an existing scalar “is” filter to “is one of” keeps the scalar (`:1986-2001`) while the adapter expects an array, and `isFilterReady` at `:295-302` treats that scalar as ready. Query/save then reject an apparently complete filter. Keep editable text until membership parsing is appropriate, and clear or normalize values when operator shape changes. Regression: type two comma-separated values character by character, switch scalar/membership operators, query and save.

**BR3-08 — Changing a filter field drops keyboard focus (new CTRL-O04 accessibility defect).** The filter row key includes `filter.fieldId` at `server-backed-views-workspace.tsx:1927-1945`. Choosing another field changes the key and remounts the focused Select instead of letting a keyboard user continue to Condition and Value. Give each draft filter a stable UI key across field edits and test focus after keyboard field selection. This is source-confirmed; any browser observation is separated below.

**BR3-09 — Field purge can strand a saved Dashboard chart (new Dashboard lifecycle defect).** For a FIELD target, `module_ids` is empty in `backend/app/systems/sandbox/lifecycle/batch_dependencies.py:45-53`, so the Dashboard-widget dependency scan at `:97-111` is skipped. Yet a persisted chart may reference that field in its query, dimension, date field, or measure (`backend/app/systems/openview/dashboards/router.py:133-163`). Purge can physically remove the field, leaving a saved chart whose configuration fails later validation, with no FK on the JSON reference. Add a field-reference blocker or deliberate audited repair in lifecycle planning/execution; retain valid saved charts and existing module-level handling. Regression: save a chart referencing a field, preview and execute FIELD purge in a disposable database, then assert purge is blocked or the chart remains valid. This is a direct source-path finding, not an executed destructive reproduction.

**BR3-10 — Two new HTTP tests fail the required frontend format gate (new verification regression).** `npm run check` exits 1 at Prettier because `frontend/tests/http/openview-charts.spec.ts:498` and `frontend/tests/http/openview-dashboards.spec.ts:1055-1065` differ from the configured format. Lint and typecheck pass separately, and all 54 affected HTTP cases pass, but the repository's combined frontend check cannot pass. Format only these test expressions; do not change assertions or product behavior. Regression: `npm run check` exits 0.

**BR3-11 — Clearing a number filter silently changes it to zero (new CTRL-O04 defect).** `frontend/src/components/systems/openview/components/server-backed-views-workspace.tsx:279-281` applies `Number("")`, yielding `0`; the controlled input cannot remain blank, and `isFilterReady` at `:295-302` treats the unintended zero as complete. Clearing a number filter can therefore query or save `= 0` without the user's intent. Preserve empty/transitional input before numeric conversion. Regression: enter a number, clear it, and assert the filter remains visibly incomplete and no zero-valued query/save is sent. This is source-confirmed; no live numeric-clear reproduction was run.
