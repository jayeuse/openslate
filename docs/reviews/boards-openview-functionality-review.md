## C. Findings

### P1 — high

**R-01 — Production can pass the development-only application-data reset guard (new safety defect).** `backend/operations/reset_application_data.py:155-175` calls `instance_target_for_process()` then accepts any non-null target. `backend/app/core/config/instance.py:230-251` deliberately constructs a config-only production target; `backend/operations/reset_planning.py:80-104` accepts its URL. Under `ENVIRONMENT=production`, matching owner URL, configured storage root, valid TTY, and correct digest, the reset can reach deletion against the production database and private files. The expected contract is a development-only local reset (`docs/architecture/15-error-handling-and-recovery.md:13`, `README.md:249-294`); the actual guard does not exclude production. The TTY/digest reduce accidental execution but do not restore the environment boundary. **Impact:** potentially severe production data loss if the utility is invoked with production configuration. **Smallest correction:** reject non-development/test environments before opening a connection in this utility; retain the general production target path for legitimate operators. **Regression test:** a production-configured reset must fail before `connect()` or storage enumeration even with otherwise valid target settings.

**R-02 — Compose `exec`/`run` bypasses worktree database-ownership preflight (new safety defect).** `scripts/environment.py:481-489` checks only a limited set of Compose subcommands; `main()` still dispatches all accepted arguments at `scripts/environment.py:890-904`. With a copied Compose project identity, `compose exec postgres ...` or `compose run postgres ...` can target another project's database without the attestation/live volume check required by Phase 0. Expected: wrong or unknown instance fails before a mutating process. Actual: these commands skip `_preflight_compose_mutation`'s ownership path. **Impact:** operator commands can mutate the wrong local database through the wrapper. **Smallest correction:** reject these database-capable subcommands or apply the same exact container/volume/cluster preflight before dispatch; preserve the existing guarded `up`/`down` flow. **Regression test:** a mismatched-worktree `exec`/`run postgres` request must be rejected before `run_compose()`.

**R-03 — Decimal View filters send a JSON number to a string-only backend (new functional defect).** `frontend/src/components/systems/openview/components/server-backed-views-workspace.tsx:262-271,2025-2045` converts `decimal` input through JavaScript `Number`. The backend's `backend/app/systems/sandbox/fields/validation.py:20-25,307-312` requires a canonical decimal string, reached by `backend/app/systems/sandbox/records/query.py:70-95`. Entering an ordinary decimal comparison under CTRL-O04 should filter real rows; instead the query receives a number and returns 422. Large decimal values also lose precision before the request; the same converter can round integers beyond JavaScript's safe range. **Impact:** core decimal filtering is broken, and high-precision filters can be incorrect. **Smallest correction:** retain decimal text through the query adapter; reject unsafe integer input with clear feedback unless an exact-string integer filter contract is separately approved. Preserve ordinary number-field behavior. **Regression test:** UI request and real PostgreSQL query for decimal `1.25` and exact decimal `9007199254740993` preserve type and precision; unsafe integer input is not silently rounded.

**R-04 — Dirty live Dashboard drafts are discarded on workspace navigation (new UI regression).** `frontend/src/components/systems/openview/components/server-backed-dashboards.tsx:395-402` knows when the draft is dirty and guards its own list actions, but does not register `useWorkspaceNavigationGuard`. The shared default in `frontend/src/components/workspace-navigation-guard.tsx:22,31-47` accepts navigation, while the prior OpenView screen guarded dirty Dashboard transitions at `frontend/src/components/systems/openview/page.tsx:657-685`. Switching to Charts, Boards, or another workspace page unmounts this component and loses unsaved edits without confirmation. CTRL-O14–O19 expect a usable durable editor whose unsaved draft survives cancellation. **Impact:** silent user work loss. **Smallest correction:** register the existing navigation-guard pattern and a discard/cancel confirmation for this component; retain the current layout and local list guards. **Regression test:** edit a saved Dashboard, navigate away by section and workspace link, cancel, and confirm the draft remains; only explicit discard proceeds.

### P2 — medium

**R-05 — Late Dashboard pagination responses can enter the wrong list (new async-state defect).** `frontend/src/components/systems/openview/components/server-backed-dashboards.tsx:565-603` lets a user switch active/archived mode while `loadMoreDashboards()` is pending, then unconditionally appends the old-mode page. The same unkeyed completion pattern at `:626-645` can overwrite field pagination state after the builder's module changes at `:1212-1216`. Expected: only responses for the current list/module change visible state. Actual: a delayed old request may show archived items under “Your dashboards,” mix page offsets, or present the wrong field continuation. **Impact:** localized incorrect lists and confusing widget choices under ordinary latency. **Smallest correction:** key or cancel each completion by current mode/module and request generation; keep the existing pagination UI. **Regression test:** delay each load-more response, change the controlling selection, then release it and verify no cross-list/module append.

**R-06 — Source-record purge removes Board placements without advancing Board revision (staged integration defect).** `backend/app/systems/sandbox/lifecycle/execution.py:148-153` deletes `BoardRecordPlacement` rows during a record/module purge. Normal placement add/remove locks the Board and increments its revision at `backend/app/systems/boards/placement_router.py:179-205,209-233`. A Board read before purge and updated afterward can retain its old revision despite changed linked records, undermining the explicit revision conflict contract for CTRL-B08 and the staged Board foundation. The Board route is not registered yet, so this is a pre-exposure consistency issue, not a demonstrated live Board UI regression. **Smallest correction:** lock and advance each affected surviving Board once during the audited purge transaction (or explicitly define a separate placement revision contract before enabling the route). **Regression test:** purge a linked record, assert the surviving Board revision changes, and reject a mutation using its pre-purge revision. Existing `backend/tests/boards/test_lifecycle.py:189-199` asserts row removal but not revision.

**R-07 — Changed private-View access test cannot reach its intended assertion (new test regression).** A fresh isolated run failed reproducibly at `backend/tests/views/test_access.py:44-47` inside `create_view()`: `backend/tests/record_queries/test_database.py:35-41` builds a Module with default `is_schema_accepted=False`, while the new live View endpoint requires `True` at `backend/app/systems/openview/views/router.py:87-99`. The test is meant to prove private views remain owner-only even to an administrator; it now exits before creating a View. **Impact:** the Views batch cannot pass, and that security assertion is untested. This is a fixture/acceptance failure, not evidence that the production authorization rule fails. **Smallest correction:** give these View fixtures an accepted module without weakening the production guard. **Regression test:** run the full Views access file with zero skips and verify its owner/admin assertions execute.

**R-08 — Disposable review runner omits the required PostgreSQL cluster identity (new isolation/verification defect).** The changed runner starts a unique labeled container and private anonymous volume at `backend/tests/postgres_runtime.py:277-305`, then `assert_owned()` checks the Docker label/image at `:356-368`, but it neither sets nor verifies `cluster_name`. A live query in this review returned an empty `cluster_name`. Phase 0 explicitly requires setting and checking that value (`docs/plans/boards-openview-functionality-plan.md:150-161`) before database operations. The label, manifest, role/URL guard, isolated network, and volume substantially limit wrong-target risk, so this is not evidence of a wrong-target write; it is a missing independent identity check and prevents full strict-isolation acceptance. **Smallest correction:** assign a per-run cluster name and compare the live value alongside container/volume and connection identity before migrations/tests. **Regression test:** a missing or mismatched live cluster name fails the runner target preflight before mutation.

### Unresolved risks, not confirmed findings

- A Views URL with `view=<uuid>` but no `module` is canonicalized to the first module and drops the view ID at `server-backed-views-workspace.tsx:375-380`; later code tries to resolve that ID. Plan §9 explicitly selects the first active module when none is supplied, so whether a view-only URL must resolve its own module needs a contract decision. Ordinary generated links should be checked before treating this as a required correction.
- A record deep link uses generic UUID text search at `server-backed-views-workspace.tsx:475-483`, compiled as `CAST(records.id AS text) ILIKE '%…%'` at `backend/app/systems/sandbox/records/query.py:133-140`. This likely bypasses the UUID index and runs count plus page queries, but no large-module measurement was made. Prefer measurement before changing the query path; `GET /api/records/{record_id}` may offer a narrower lookup if the projection contract fits.
- Current real-stack browser coverage uses an empty business dataset for Chart/Dashboard snapshots and does not download a populated export (`frontend/tests/fullstack/sandbox-workspace.spec.ts:174` onward). Mocked HTTP specs and PostgreSQL query tests do not establish the combined populated UI/export workflow. This is missing acceptance evidence, not a demonstrated product defect.
