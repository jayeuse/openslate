# Lifecycle and State Management

> **Scope:** Domain close/reopen/purge state and file scanning state.

Departments, modules, fields, records, and relationships have explicit lifecycle behavior. Ordinary deletion requests a controlled close flow where required. Services compute impact, require confirmations, acquire locks, revalidate scope, make individual ORM changes, and record audit entries. Purge is disabled by default through `LIFECYCLE_PURGE_ENABLED=false`.

Password challenges for destructive lifecycle work ask Supabase Auth to verify the current email/password through [`ProviderPasswordGrantClient`](../../backend/app/systems/sandbox/lifecycle/password.py). The verified provider subject must resolve to the same eligible OpenSlate actor that opened the challenge; its temporary provider session is signed out rather than admitted as an application session. [`verify_challenge`](../../backend/app/systems/sandbox/lifecycle/challenge_verification.py) locks and validates the challenge before consuming it, rejects expired or already-used challenges, and does not treat a browser cookie as proof of the requested password action.

Application file metadata remains in the OpenSlate PostgreSQL schema while bytes move through private Supabase Storage quarantine and ready buckets. The OpenSlate [scanner worker](../../backend/app/systems/platform/files/worker.py) fetches quarantined bytes through the [Storage adapter](../../backend/app/systems/platform/files/supabase_storage.py), checks integrity, and uses ClamAV before promotion. Only a verified clean verdict permits authorized download. Scanner uncertainty blocks publication. Restart recovery preserves pending work and does not make a missing or uncertain scan result clean.

After a committed audit-aware mutation, the [event publisher](../../backend/app/systems/platform/events/publisher.py) sends an opaque PostgreSQL `LISTEN`/`NOTIFY` invalidation for authenticated SSE. Supabase Realtime is not used for this flow. Notification failure does not roll back the business transaction; consumers resynchronize by reading authorized resources again. See [infrastructure](11-infrastructure.md#storage-and-scanning) and [runtime flows](13-runtime-flows.md).
